Linux I/O control room

`dd` 的每個選項，
在控制哪一段搬運？

別把 `sync` 當成一個意思。用一條資料搬運帶，把輸入、區塊、轉換規則與輸出耐久性拆開看。

一眼看懂

資料不是直接「複製」；它要穿過四個站

① if=輸入從哪裡讀
→
② iflag=讀取端怎麼開檔
→
③ conv=資料如何處理
→
④ oflag= / of=往哪裡、怎麼寫
先懂這個：iflag 管讀取端，oflag 管寫入端，conv 是資料處理規則；三者不是同一類開關。

控制台：點選你想釐清的旗標

別混淆：相同單字，不同工作

寫法主要效果適合先問的問題
conv=sync短的輸入 block 以 NUL 補齊我要的是固定大小的資料 block 嗎？
oflag=sync每次寫入使用同步語意每一筆寫入都需要較強耐久性嗎？
conv=fsync結束前對輸出做 fsync我是在意整次 copy 結束時落盤嗎？
iflag=fullblock讓 count 對 pipe 的短讀取更符合完整 block 計數輸入是否可能來自 pipe？

安全收束：先看目標，再談效能

  1. 先用 lsblk 核對 of=，不要靠裝置名稱印象。
  2. 把「讀、轉、寫」各自的需求講清楚。
  3. 寫完以 hash、mount 或實際讀回驗證，不只看 exit code。
常見誤解：conv=sync 不等於把磁碟資料 flush；它處理的是短輸入 block 的填補。
這是一份新手導向的心智模型；涉及正式系統或資料寫入時，請先在可回復的測試環境驗證。

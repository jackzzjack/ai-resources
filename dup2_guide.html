dup2()：把資料流接到另一個檔案描述元

dup2(oldfd, newfd) 讓 newfd 成為 oldfd 的複本。它是 shell 的 > 與 | 背後，把 stdout 接到檔案或 pipe 的核心動作。

定義運作流程C 範例常見陷阱如何驗證

先抓住心智模型

FD 是插座

stdin=0、stdout=1、stderr=2。

原子替換

newfd 已開啟時，dup2 先關閉它再替換。

共享底層狀態

複本共享同一個 open file description。

exec 也保留

未設 close-on-exec 的 FD 可跨過 exec。

程序與資料怎麼走？

01 SOURCE開啟檔案或 pipe，取得 oldfd。
02 TARGET決定覆蓋 stdin、stdout 或 stderr。
03 DUP2讓 newfd 指向同一個底層描述。
04 CLOSE關閉多餘端，避免 FD leak。

可編譯範例

先把範例存成 C 檔，再用編譯器實際跑一次；系統呼叫要同時用程式碼、輸出與資源生命週期理解。

#include <fcntl.h> #include <stdio.h> #include <unistd.h> int main(void){ int fd=open("result.txt",O_WRONLY|O_CREAT|O_TRUNC,0644); if(fd<0){perror("open");return 1;} if(dup2(fd,STDOUT_FILENO)<0){perror("dup2");return 1;} close(fd); printf("this line goes to result.txt\n"); fflush(stdout); return 0; }

預期輸出

$ cc -Wall -Wextra -o dup2-demo dup2-demo.c && ./dup2-demo && cat result.txt

常見陷阱與改法

現象原因建議
忘記關閉舊 FDdup2 後常留下重複 descriptor。適時 close oldfd。
stderr 導錯只導 stdout 時錯誤仍到終端。對 STDERR_FILENO 再 dup2。
pipe 不會 EOF仍有程序握 write end。每個 process 關掉不用端。
oldfd == newfd此時 dup2 不做事。不應再 close 它。

驗證方式

□ 以 cc -Wall -Wextra 編譯，確認沒有 warning。
□ 實際執行範例，確認輸出符合預期。
□ 改動一個輸入或分支，觀察結果如何改變。
□ 若系統提供 strace，觀察相關系統呼叫順序。
安全提醒：先在測試目錄執行範例，並對所有系統呼叫檢查回傳值。

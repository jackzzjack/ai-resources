COMMIT CHECKPOINT

pre-commit：
程式碼提交前的安檢門

把快而可預期的品質檢查放在 git commit 前；它補強本機回饋，並不取代遠端 CI。

安檢模擬器責任分工導入路徑

一眼看懂：提交前會發生什麼？

選一種提交狀態，看看哪些關卡攔下變更。這是概念示意，不會讀取你的檔案。

三道防線，各自負責什麼？

01｜暫存區

開發者決定哪些變更進入這次提交。

02｜pre-commit hooks

依設定檔跑 formatter、lint、型別或秘密掃描，失敗就回到修正。

03｜CI

在遠端以完整環境重現關鍵檢查；不能因本機 hook 而省略。

先懂這個：hooks 應保持快速、可預期且有明確修正訊息；太慢的本機門檻只會讓人想繞過它。

漸進導入，而不是一次塞滿規則

階段先做什麼成功訊號
1格式化團隊 diff 不再充滿純格式噪音
2lint／型別檢查常見錯誤在 commit 前回饋
3安全與專案規則明確界定哪些規則必須同時留在 CI

常見誤解：跳過 hook 不會讓問題消失；因此重要規則仍應在 CI 可重現地執行。

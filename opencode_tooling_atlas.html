四類工作，不要混用

問題先看哪類工具
官方 API 怎麼用？Context7／官方文件
外部世界有哪些資料或觀點？Exa
別人如何實作這段程式？grep.app
程式裡哪個符號、呼叫或結構該改？LSP／ast-grep
使用者真的看得到成果嗎？Playwright
先懂這個：文字搜尋找到的是字面相似；語意與 AST 工具看的是程式結構。它們能縮小修改範圍，但仍要用測試與 review 確認行為。

一個安全的代理工作流

1. 先查規格

以官方文件或 Context7 建立可用版本與限制；需要外部脈絡時再用 Exa。

2. 再找程式位置

先以 LSP 跳到定義、找引用與看診斷；要做一致的結構性盤點或修改時，使用 ast-grep。

3. 用案例交叉檢查

grep.app 可提供公開程式碼的閱讀線索，不等於可直接複製的權威答案或安全範例。

4. 從使用者視角驗證

Playwright 操作真實瀏覽器頁面，檢查互動、可見文字與流程是否真的到達預期狀態。

常見誤用：把搜尋結果當事實、把找到的程式片段當相容實作，或只看程式沒有跑使用者流程。工具的價值是讓每個假設更容易被檢查，不是跳過檢查。

sgdisk：把 GPT 變更
當成一次受控任務

sgdisk 擅長自動化，但不會替你辨識「哪一顆才是測試磁碟」。把它想成飛行檢查表：定位 → 備份 → 變更 → 驗證，每一站都要留下可核對的證據。

GPT 地圖任務流程指令與範圍變更控制台起飛前清單

一眼看懂：sgdisk 改的是「目錄」，不是分割區裡的資料

GPT 在磁碟開頭與結尾保存 header 與 partition entries。entry 描述 LBA 範圍、Type GUID、Unique GUID、名稱與 attributes；檔案系統、掛載與映像複製是下一層的工作。

/dev/sdX · GPT map先看，不先改
EFIentry #1 · type / label / LBA rangemetadata
rootentry #2 · type / label / LBA rangemetadata
dataentry #3 · type / label / LBA rangemetadata

主 GPT header + entries ↔ 備份 header + entries。sgdisk -v 會協助檢查這份地圖是否一致。

sgdisk 負責GPT metadata列出、建立、刪除、命名、設定 type 與 attribute。
sgdisk 不負責檔案系統內容格式化、mount、寫 image、資料備份要用其他工具與驗證。
先懂這個：「partition #3」是 entry 的編號，不是永恆的角色名稱。自動化應優先用可驗證的 label、PARTUUID、Type GUID 與 layout 文件，而不是只假定 /dev/sdX3 永遠相同。

任務航線：先把不可逆風險移到最前面

這不是一串可直接複製的神奇指令；它是把「我是不是正在碰錯磁碟？」這個問題放在任何寫入之前的流程。

01 · IDENTIFY

辨識裝置

lsblk 看型號、大小、掛載點；確認不是系統碟。

02 · INSPECT

讀取現況

sgdisk -p -v 記錄 layout 與一致性。

03 · BACK UP

保存地圖

-b 備份的是 GPT 結構，不是檔案內容。

04 · CHANGE

最小變更

明確指定 entry、範圍、名稱與 type；避免模糊的批次操作。

05 · VERIFY

再讀一次

重新 -p -v，再以 lsblk 與實際使用情境驗證。

常見誤解：sgdisk -b 只備份 GPT metadata。它不能還原分割區內的檔案、檔案系統或 OS image；資料保護仍要有獨立的備份策略。

指令對照：每個動作都要知道「會動到哪個層次」

目的範例（以 lab 裝置為例）它回答／改變什麼接著驗證
列出 layoutsudo sgdisk -p /dev/sdX讀取 GPT entries、範圍與名稱。比對大小、entry 編號與預期 layout。
檢查一致性sudo sgdisk -v /dev/sdX檢查 GPT 結構的已知問題。先處理診斷，再談建立或刪除。
備份 metadatasudo sgdisk -b gpt-backup.bin /dev/sdX將 GPT header 與 entries 存檔。保存到另一個安全位置，標記來源裝置與日期。
建立 entrysudo sgdisk -n 3:0:+512M -c 3:demo -t 3:8300 /dev/sdX建立 #3、指定大小、名稱、Linux filesystem type。sgdisk -p -v；再確認 kernel 是否已重新讀表。
看單一 entrysudo sgdisk -i 3 /dev/sdX檢視 #3 的 GUID、範圍與 attributes。把結果對回 layout 文件與需求。
# 僅在已確認的測試磁碟操作：
lsblk -o NAME,SIZE,MODEL,MOUNTPOINTS
sudo sgdisk -p -v /dev/sdX
sudo sgdisk -b gpt-backup.bin /dev/sdX
# ...執行一個明確、可回顧的 layout 變更...
sudo sgdisk -p -v /dev/sdX
lsblk -o NAME,SIZE,PARTLABEL,PARTUUID /dev/sdX

變更控制台：先選你所在的站，再決定下一步

點選目前情境，控制台會顯示「現在該做什麼」與「現在不該做什麼」。這是任務狀態機，不會真的執行磁碟指令。

停止條件：如果 lsblk 的大小、型號、掛載點或裝置名稱有一項與預期不符，停止。不要用「看起來差不多」補足不確定性；先取得正確設備資訊。

起飛前清單：一個可靠的 sgdisk 任務應留下什麼

□ 裝置身分

記下 model、size、serial（若可用）與掛載點；確認 lab / production 範圍。

□ 變更前證據

保存 sgdisk -p -v 的輸出與 GPT metadata backup。

□ layout 契約

entry 編號、LBA、label、Type GUID、A/B slot 與 rollback 規則有明確來源。

□ 變更後證據

重新驗證 GPT、kernel 視圖與使用案例；必要時在 loop device 或 lab 先演練。

你可以這樣想：sgdisk 不是「分割磁碟的按鈕」，而是一支把磁碟地圖改寫得很精準的筆。愈精準的筆，愈需要先確認自己正在寫的是哪一張地圖。

GNU Make · Linux · 設定控制台

Makefile 的值，
到底是誰最後說了算？

Makefile 難的常不是 target，而是設定像多個控制室依序接手：賦值何時展開、include 何時載入、命令列何時覆蓋。這頁把它變成一台可追蹤訊號來源的控制台。

控制台賦值時鐘載入走廊優先權設定模擬器除錯儀表

一眼看懂：Makefile 是「設定訊號控制台」

每一份設定都不是孤立的。先有讀檔順序，再有變數的展開方式，最後才由較高優先權的來源決定結果。

訊號路徑
defaults.mk
預設
platform.mk
平台
local.mk
本機
make VAR=…
命令列

問題不是「哪個檔案有 CFLAGS？」而是「最終值的每一段從哪裡來？」

最小心智模型讀取 → 展開 → 選勝者
$ make print-config
LOAD defaults.mk → platform.mk → local.mk
FLAVOR CFLAGS = simple
ORIGIN CFLAGS = command line
FINAL CFLAGS = -Wall -O2 -g
先懂這個：include 是把另一份 Makefile 的內容插進目前讀取的位置，不是建立獨立命名空間。它像把另一張設定單放到同一本資料夾裡，後面的行仍然看得到前面的變數。

賦值時鐘：四種寫法在不同時刻按下快門

=

延後拍照

保存右側文字；每次取用才展開。後續變數改動會影響結果。

:=

立刻定格

讀到這行就展開一次。適合快取 shell、wildcard。

?=

缺席才補位

只在未定義時提供預設，讓使用者或上游仍能指定。

+=

接上訊號

追加內容，並保留原變數原本的 recursive / simple 特性。

同一段文字，兩個時間點

BASE = hello
LATE = $(BASE) world
NOW := $(BASE) world
BASE = hi
# LATE → hi world
# NOW  → hello world

可覆寫的安全預設

CC ?= gcc
CFLAGS := -Wall -Wextra
CFLAGS += -O2
# make CC=clang
# CC 不被覆蓋，CFLAGS 仍累積
常見誤解：?= 不是「永遠最低優先權」的魔法；它只是當下發現變數未定義才賦值。要判斷最終來源，請用 $(origin VAR)，不要靠猜。

載入走廊：include 不是隔離，是把設定排成一條隊

把專案拆成多個檔案很合理；關鍵是讓讀者一眼看出「誰先提供預設、誰可做平台調整、誰只留在本機」。

1
defaults.mk專案可提交的保守預設，例如警告旗標、預設工具。
CFLAGS ?= -Wall
2
platform.mk依 OS、架構或 toolchain 做明確調整。
CFLAGS += -march=…
3
local.mk開發者本機覆寫；通常不提交，必須是 optional。
-include local.mk
4
rules.mk最後載入規則；它會看見前面已決定的設定。
include rules.mk

include：檔案應存在

讀不到通常就是錯誤。用在專案必要的共用規則與預設設定，能及早發現 checkout 不完整或路徑拼錯。

include config/defaults.mk
include config/platform.mk
include rules.mk

-include：本機可選

讀不到時繼續。常用於每人不同的 local.mk 或自動產生的 dependency 檔。

-include local.mk
-include $(DEPS)

# local.mk 不應意外變成必需品

優先權不是單純的「最後一行贏」

檔案內的讀取順序很重要，但設定還可能來自命令列、環境與 override。把來源與目的分開，才不會把維護策略寫成偶然結果。

來源適合用來做什麼除錯時問的問題
defaults.mk可攜、可提交的專案基準這是預設還是硬性政策？
後續 include平台或產品線的明確差異它是在預設之後載入嗎？
命令列 make VAR=x一次性實驗、CI 參數、使用者選擇origin 是否顯示 command line？
override少數必須壓過命令列的專案政策為什麼使用者不能改？能否改成明確開關？
你可以這樣想：讀檔順序決定「有哪些候選值」；賦值型態決定「何時算」；來源優先權決定「誰能蓋過誰」。三件事混在一起時，Makefile 才會看起來像魔法。

設定模擬器：點一個情境，看最終值如何被組裝

這不是通用按鈕：它把同一個 CFLAGS 在 include、local override 與命令列三種情境的載入證據攤開。

除錯儀表：別只印值，也印它的身世

三個最有用的探針

$(info CFLAGS=$(CFLAGS))
$(info origin=$(origin CFLAGS))
$(info flavor=$(flavor CFLAGS))

print-config:
	@true

把它放在載入鏈之後，或做成明確的 make print-config target；你會同時看見值、來源與展開型態。

新手導讀順序

  1. 先比較 = 與 := 的時間差。
  2. 再讓 ?= 與命令列相遇。
  3. 接著把設定拆成 defaults / platform / local 三層。
  4. 最後才處理 override 與環境變數政策。
01載入可讀

把 include 順序集中在入口，避免設定散落。

02覆寫有意圖

本機、CI、平台差異各有專屬入口。

03最終可觀測

提供 print-config，而不是讓人搜索整個 repo。

收束：把 Makefile 想成控制台，不是堆滿等號的文字檔。當每個設定都能回答「何時展開、何時載入、誰最後覆蓋」，你就能從猜測回到可驗證的建置行為。

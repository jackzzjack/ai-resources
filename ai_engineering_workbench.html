從一句 prompt 到可驗證任務：五層工作台

Prompt、context、harness、loop、graph 不是互相取代的流行詞；它們分別管理指令、工作記憶、行動護欄、反覆校正與多步任務關係。

任務控制面板
01 · Prompt engineering把這一回合的目標、格式與限制說清楚。
02 · Context engineering挑選、壓縮、更新完成任務真正需要的文件與狀態。
03 · Harness engineering把工具、權限、沙盒、測試與觀測接成可控的執行環境。
04 · Loop engineering安排觀察、執行、評估、修正，讓錯誤能被下一輪吸收。
05 · Graph engineering表達節點、依賴、分支與交接，避免長任務只靠線性對話記憶。
一次回答

先把答案的任務契約說清楚

主要優先處理 prompt；若背景不足，再補必要 context。此時工具、迴圈與圖狀控制未必是第一個瓶頸。

你可以這樣想：先寫好一道題目，不等於已經建好一間自動化工廠。

失敗 → 對應層

格式跑掉：prompt。引用錯資料：context。工具誤動作：harness。做錯後不修：loop。依賴順序混亂：graph。

先懂這個

更長的 prompt 不會自動變成 context engineering；加入工具也不會自動形成可靠 agent。

新手閱讀順序

先用一次問答辨認 prompt／context；再走工具任務的護欄；最後看迴圈與圖如何支撐長流程。

選型矩陣

層級主要對象可觀察訊號適用時機
Prompt單回合指令格式、遵循度答案目標不清
Context任務記憶引用、遺漏、過期背景分散
Harness執行環境權限、測試、紀錄模型要操作工具
Loop校正節奏評估與修正率結果需反覆改善
Graph任務關係依賴、分支、交接多步或多人協作

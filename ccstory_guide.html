ccstory：把一週的 coding session
走成一條能回看的走廊

ccusage 告訴你花了多少；ccstory 想回答「這些時間究竟做了什麼」。它讀取本機的 coding-agent 工作紀錄，將活動、分類與摘要整理成回顧報告。

回憶走廊資料旅程第一次使用隱私邊界工具對照

一眼看懂：別從終端機捲動條找故事

選一張入場券，看看 ccstory 想把零散紀錄轉成哪一種可行動的回顧。以下是概念示意，不是你的真實 session 資料。

先懂這個：ccstory 的「故事」是回顧輔助，不等於事實驗收或工時系統。把它當成找回脈絡的入口，重要成果仍應回到程式碼、issue、PR 與團隊紀錄驗證。

資料旅程：從本機 session 到一份 recap

01 · 收集

讀取已支援 coding agent 的本機工作紀錄；目前版本涵蓋 Claude Code、Codex 與 Antigravity。

02 · 分類

依專案資料夾規則分類；可選擇內容感知分類，並保留可設定的分類規則。

03 · 彙整

把 session 聚合成時間窗、類別、專案與趨勢；平行工作以去重後的牆鐘時間呈現。

04 · 回顧

輸出 terminal card、Markdown、JSON 或趨勢，方便寫週報、反思與下一輪規劃。

本機來源

session、專案與本機 Git 活動提供工作脈絡。

ccstory 規則

分類、快取與報告格式將原始活動整理成一致的回顧。

你的判斷

閱讀報告後，選擇要保留、驗證、交接或調整的工作方式。

第一次使用：先跑一份最小、可理解的回顧

以下以專案 README 所示流程為準；請在自己的 Python 與 pipx 環境中執行，並先閱讀工具目前版本的說明。

pipx install ccstory
ccstory init
ccstory week

# 不使用網路與敘事後端的最小首次回顧
ccstory init --skip
ccstory week --minimal --classify folder --no-artifacts
先看 week

用過去七天建立第一個時間窗，而非立刻把整個歷史當作一團資料。

再調分類

確認資料夾規則是否把專案放進合理的工作桶。

最後才升級敘事

需要更精緻逐 session 描述時，再理解並選用相應的 narrator 設定。

隱私邊界：它讀什麼、什麼時候可能連網？

本機工作紀錄

工具會讀取支援 agent 的本機資料來源來建立 recap；先確認你的電腦、帳號與共享環境是否合適。

可選的敘事後端

內容分類或 LLM narrative 取決於設定的本機 CLI／服務；它與純本機最小模式不同。

可選的 artifacts

GitHub／PyPI metadata 可被停用；README 提供 --no-artifacts 的選項。

你可以這樣想：先把 ccstory 當成本機工作台的索引員，而非把所有內容交給一個「懂你」的黑盒。第一次執行前，先選擇資料範圍與網路行為。

這個成果真的合併了嗎？可提供線索，但不是最終證據。回到 commit、PR 狀態、release 與測試結果確認。
我下週該從哪裡接手？用週／月回顧找出未完主題與活動脈絡。用 issue、看板與待辦管理正式承諾。

select()：一次等待多個 I/O 事件

select() 讓單一程序先等一組檔案描述元可讀、可寫或有例外再動作。它不是 read，而是 I/O 多工的等待站。

定義運作流程C 範例常見陷阱如何驗證

先抓住心智模型

可讀不等於讀完

可能有資料，也可能已到 EOF。

可寫不等於全寫完

至少可寫一些資料，仍要處理 partial write。

集合會被改寫

select 回來後 fd_set 只留 ready FD。

有數量限制

FD_SETSIZE 與掃描成本適合 FD 不大的情境。

程序與資料怎麼走？

01 SET把欲監看的 FD 放進 fd_set。
02 TIMEOUT傳 timeval；NULL 代表永久等待。
03 WAIT等 FD ready、逾時或被 signal 中斷。
04 CHECK用 FD_ISSET 找 ready FD，下一輪重建集合。

可編譯範例

先把範例存成 C 檔，再用編譯器實際跑一次；系統呼叫要同時用程式碼、輸出與資源生命週期理解。

#include <stdio.h> #include <sys/select.h> #include <unistd.h> int main(void){ fd_set reads;FD_ZERO(&reads);FD_SET(STDIN_FILENO,&reads); struct timeval t={.tv_sec=5,.tv_usec=0}; int ready=select(STDIN_FILENO+1,&reads,NULL,NULL,&t); if(ready<0){perror("select");return 1;} if(ready==0){puts("timeout: no input in 5 seconds");return 0;} char line[128];if(fgets(line,sizeof line,stdin))printf("received: %s",line); return 0; }

預期輸出

$ cc -Wall -Wextra -o select-demo select-demo.c && ./select-demo

常見陷阱與改法

現象原因建議
重複用舊 fd_setselect 會修改集合。每輪從 master set 複製。
nfds 填錯第一參數是最大 FD + 1。追蹤 maxfd。
忽略 EINTRsignal 可讓 select 回傳 -1。檢查 errno，必要時重試。
大量 FD每輪 O(n) 掃 FD。Linux 大量 FD 考慮 poll/epoll。

驗證方式

□ 以 cc -Wall -Wextra 編譯，確認沒有 warning。
□ 實際執行範例，確認輸出符合預期。
□ 改動一個輸入或分支，觀察結果如何改變。
□ 若系統提供 strace，觀察相關系統呼叫順序。
安全提醒：先在測試目錄執行範例，並對所有系統呼叫檢查回傳值。

SSH 免輸入密碼：
兩把鎖的信任握手

不是取消驗證，而是把「每次輸入密碼」換成「本機證明自己持有私鑰」。私鑰不離開你的裝置，伺服器只保存用來驗證的公鑰。

兩把鎖握手流程首次部署信任儀表方法比較安全收尾

一眼看懂：一把留在本機，一把放在伺服器

把 SSH 金鑰想成一組能互相驗證的鎖。遠端不是「知道你的私鑰」，而是用你預先交付的公鑰，檢查你能否對本次登入的挑戰做出正確簽名。

💻 你的本機

PRIVATE KEY
~/.ssh/id_ed25519

● 私鑰留在這裡；可再用 passphrase 保護

⇄

🖥️ 遠端帳號

PUBLIC KEY
~/.ssh/authorized_keys

● 只保存公鑰，供 sshd 驗證簽名

先懂這個：ssh-copy-id 複製的是 公鑰，不是私鑰；它只是把公鑰安全地追加到遠端帳號的 authorized_keys。

登入不是傳遞祕密，而是一場簽名驗證

1

連線

本機向 sshd 宣告可使用的公鑰身分。

2

出題

伺服器確認此公鑰在 authorized_keys 裡，送出本次挑戰。

3

簽名

本機用私鑰對挑戰簽名；私鑰不經網路傳送。

4

驗證

伺服器以保存的公鑰檢查簽名是否正確。

5

登入

驗證成功才開啟 shell 或指定服務。

常見誤解：「不再輸入帳號密碼」不代表完全無保護。私鑰若沒有 passphrase、裝置被竊又未撤銷，風險仍然存在。

首次部署：每一步都要有可驗證的結果

以下假設你仍可用密碼登入遠端。請把 user@example.com 換成自己的遠端帳號與主機；不要在不確定目標時複製指令。

01 先盤點

看現有金鑰

$ ls -la ~/.ssh

避免不必要地覆蓋既有的 id_ed25519；公司或團隊環境也可能已有管理規範。

02 產生

建立 Ed25519 金鑰

$ ssh-keygen -t ed25519 -a 100 -C "my-laptop"

為私鑰設定 passphrase；-a 100 是 KDF rounds 的常見強化選項。

03 安裝公鑰

交給正確帳號

$ ssh-copy-id -i ~/.ssh/id_ed25519.pub user@example.com

初次可能仍需輸入遠端密碼，目的只是完成公鑰部署。

04 先測再收緊

強制只試公鑰

$ ssh -o PreferredAuthentications=publickey -o PasswordAuthentication=no user@example.com

成功後才考慮調整伺服器密碼登入政策，且保留另一個已登入的救援 session。

信任儀表：換一種情境，下一步不同

選擇你現在所處的階段。儀表會顯示哪一段信任鏈還沒有亮燈，而不是只給一串萬用指令。

選什麼方式：便利性只是其中一格

方式日常體驗主要防護復原／撤銷重點適合情境
帳號密碼每次輸入或儲存取決於密碼強度與 MFA重設密碼、檢查登入紀錄暫時性存取或尚未管理金鑰的環境
SSH 金鑰 + passphrase可由 ssh-agent 暫存解鎖狀態私鑰持有證明；passphrase 保護遺失裝置上的私鑰從 authorized_keys 移除對應公鑰個人開發機、伺服器日常維運
硬體安全金鑰／FIDO2常需觸碰裝置確認私鑰操作受硬體保護，抗釣魚能力較佳登錄備援金鑰；遺失即撤銷高價值帳號、需要實體在場的工作
你可以這樣想：密碼像每次背出通關語；SSH 金鑰像帶著一把只能在你手上使用的簽名印章。伺服器不需要保存印章，也能驗證這次蓋章是否出自你。

安全收尾：先維持可回來的路，再關門

保護私鑰
不要傳到聊天、email、Git repo 或雲端公開空間；設定 passphrase，妥善備份或改用硬體金鑰。
驗證主機身分
首次連線核對 host key fingerprint；看到主機金鑰異常變更時，不要直接接受。
最小授權
一人／一裝置一把金鑰較容易追蹤與撤銷；不要多人共用同一私鑰。
再停用密碼登入
只有在新終端測通公鑰登入、保有救援 session 且了解遠端管理路徑時才調整 sshd 設定。
避免把自己鎖在門外：不要在唯一的 SSH session 中立刻關掉密碼登入或重啟 sshd。先另開一個 terminal 成功以金鑰登入，再考慮任何伺服器端強化。

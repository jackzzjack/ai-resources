fork()：把一個程序分成兩條時間線

fork() 建立子程序。父子從同一行程式碼往下走，卻用不同回傳值知道自己是誰；這是 Linux process 的第一個分岔點。

定義運作流程C 範例常見陷阱如何驗證

先抓住心智模型

建立 child

子程序從 fork() 回傳處繼續執行。

回傳值路標

parent 拿 child PID；child 拿 0；失敗為 -1。

不是共享變數

父子有不同虛擬記憶體；要交換資料需 IPC。

同步收尾

parent 用 waitpid() 回收 child，避免 zombie。

程序與資料怎麼走？

01 CALL呼叫 fork()。
02 CREATE核心建立 child 與新 PID，採 copy-on-write。
03 BRANCH父子都繼續執行，但拿到不同回傳值。
04 WAITparent 用 waitpid() 讀取結束狀態。

可編譯範例

先把範例存成 C 檔，再用編譯器實際跑一次；系統呼叫要同時用程式碼、輸出與資源生命週期理解。

#include <stdio.h> #include <sys/types.h> #include <sys/wait.h> #include <unistd.h> int main(void){ pid_t pid=fork(); if(pid<0){perror("fork");return 1;} if(pid==0){printf("child: pid=%ld\n",(long)getpid()); fflush(stdout); _exit(42);} int status; waitpid(pid,&status,0); printf("parent: child exited with %d\n",WEXITSTATUS(status)); return 0; }

預期輸出

$ cc -Wall -Wextra -o fork-demo fork-demo.c && ./fork-demo

常見陷阱與改法

現象原因建議
兩邊都印兩次父子都從 fork 後繼續跑。用 pid == 0 明確分支。
看到 zombiechild 結束後 parent 尚未讀取狀態。呼叫 waitpid()。
以為變數共享fork 後是不同 process。用 pipe、socket 或 shared memory。
文字重複fork 前 stdout buffer 未 flush。fork 前 flush，理解 buffer 行為。

驗證方式

□ 以 cc -Wall -Wextra 編譯，確認沒有 warning。
□ 實際執行範例，確認輸出符合預期。
□ 改動一個輸入或分支，觀察結果如何改變。
□ 若系統提供 strace，觀察相關系統呼叫順序。
安全提醒：先在測試目錄執行範例，並對所有系統呼叫檢查回傳值。

AGENT MEMORY ATLAS

Agent 的記憶，究竟該放在哪一層？

把記憶看成一座任務控制台：有的產品替應用程式保存可檢索的事實，有的替團隊維護共享工作脈絡；Hermes 則把記憶、技能、設定檔與執行 session 放在可組裝的 agent 框架中。

共享脈絡

Honcho

將人與 agent 的工作脈絡做成可共享、可延續的工作空間；適合關注跨 session 的協作記憶。

Agent 框架

Hermes Agents

不是只提供一種記憶服務：它把可設定的 memory provider 與 profiles、sessions、skills、工具調度放進執行框架。

02 / 互動微體驗

記憶路由器：先問「你要保存什麼？」

按下情境，看看需求比較接近哪種分工。這不是採購評分；實作前仍要驗證資料主權、保留期限、embedding／模型成本與供應商條款。

先懂這個：「記憶」不等於把完整聊天紀錄無限塞回 prompt。常見設計會先選擇、摘要或結構化資訊，再依任務檢索；因此要分別評估 寫入、更新、讀取 和 遺忘。
04 / 新手導讀順序

從需求，而不是品牌名稱開始

1列出要跨 session 延續的事實、偏好與任務狀態。
2決定誰可讀、誰可寫，以及如何刪除與稽核。
3選擇記憶層：產品個人化、共享工作脈絡，或 agent 可替換後端。
4用真實任務測試：是否取回正確資訊，而不是只測 API 是否回 200。
05 / 常見誤解

你可以這樣想：記憶是資料產品，不是魔法人格

選擇工具前，先定義記憶單位、資料生命週期與失敗模式。模型會變、agent 框架會換；可說明、可刪除、可驗證的脈絡邊界，才是能長期維護的設計。

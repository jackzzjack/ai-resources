CREW DRAGON · INTERFACE & RETURN MAP

兩個前端
一次平安返航

Crew Dragon 的鼻錐與主降落傘看似分居任務兩端，實際都在做同一件事：讓太空船在不同環境切換時，保留可操作、可驗證的安全邊界。

飛行外形：鼻錐關閉，保護前端對接硬體並維持氣動外形。

前端是保護罩，也是任務介面

在發射與再入階段，前端的首要工作是把外部環境與對接硬體隔開；它不是單純一扇門。

先懂這個：「能打開」只是動作；真正的系統問題是何時、在什麼狀態、以何種驗證條件切換。

1｜發射封閉前端、承受飛行環境。
2｜在軌巡航與姿態操作。
3｜靠近 ISS開啟鼻錐、露出對接介面。
4｜離站重新進入返航流程。
5｜濺落傘群減速，回收團隊接手。

四具主傘：不是四倍保險

傘群的價值在於把開傘、載荷分配、單一元件失效與海上回收放進同一條下降鏈。冗餘必須連同展開順序、結構載荷與操作程序一起判讀。

A
展開
先建立穩定、可預期的減速狀態。
B
分攤
多具主傘共同承擔下降工作。
C
回收
濺落後的定位、船舶接近與整備仍是任務的一段。

失效容忍要問的三件事

問題不能只看
一具傘異常不能只用「還有三具」替代完整的載荷與下降條件分析。
安全返航不能只看開傘瞬間；海況、姿態與回收協作也影響結果。
可重複任務不能把一次成功當成所有構型、天候與操作條件的證明。

一條任務、兩個狀態轉換器

鼻錐把「飛行外形」切換為「對接入口」；傘群把「高速再入後的太空船」切換為「可由海上團隊接手的回收物」。兩者都提醒我們：太空任務不是一台載具獨自完成，而是由載具、ISS 介面、地面控制與回收團隊接力。

常見誤解：四具主傘與可開闔鼻錐都不是單一零件的魔法。公開資料能描述任務角色；未公開的機構細節、門檻與程序不應被補成確定事實。

閱讀路徑：先切換上方三種狀態，再沿任務時間線回看「保護、開放、減速、回收」如何形成一個完整閉環。

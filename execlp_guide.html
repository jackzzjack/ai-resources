execlp()：讓子程序換上一個新程式

execlp() 不會建立新程序；它把目前程序的程式映像替換成另一個可執行檔，並從 PATH 尋找目標。通常接在 fork() 的 child 分支。

定義運作流程C 範例常見陷阱如何驗證

先抓住心智模型

l = 逐一參數

最後必須以 NULL 結束參數列。

p = PATH

依 PATH 尋找命令，例如 printf。

成功不會回來

替換成功後，原 C 程式的下一行不會執行。

失敗才回傳

只有失敗才回傳 -1 並設定 errno。

程序與資料怎麼走？

01 FORKparent 先建立 child。
02 SETUPchild 可先調整 stdin/stdout。
03 EXEC新程式取代 child 的 code/data/stack。
04 WAITparent 等待同一個 PID 的結束狀態。

可編譯範例

先把範例存成 C 檔，再用編譯器實際跑一次；系統呼叫要同時用程式碼、輸出與資源生命週期理解。

#include <stdio.h> #include <sys/wait.h> #include <unistd.h> int main(void){ pid_t pid=fork(); if(pid<0){perror("fork");return 1;} if(pid==0){ execlp("printf","printf","child runs: %s\n","hello",(char *)NULL); perror("execlp"); _exit(127); } int status;waitpid(pid,&status,0);puts("parent: child finished"); return WIFEXITED(status)?WEXITSTATUS(status):1; }

預期輸出

$ cc -Wall -Wextra -o execlp-demo execlp-demo.c && ./execlp-demo

常見陷阱與改法

現象原因建議
少了 NULLexec family 不知道參數列何時結束。最後傳入 (char *)NULL。
exec 後仍寫清理碼成功後控制權不回原程式。失敗處理緊接 exec 後。
命令找不到PATH 沒有目標或拼字錯。用 perror("execlp")。
child 回主流程失敗後 return 可能重複清理。以 _exit(127) 結束。

驗證方式

□ 以 cc -Wall -Wextra 編譯，確認沒有 warning。
□ 實際執行範例，確認輸出符合預期。
□ 改動一個輸入或分支，觀察結果如何改變。
□ 若系統提供 strace，觀察相關系統呼叫順序。
安全提醒：先在測試目錄執行範例，並對所有系統呼叫檢查回傳值。
